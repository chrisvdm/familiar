# SDK: @familiar/sdk
<!-- gh issue #13 -->

## Context

Developers building with familiar have no code-first path. The only options are curl and raw fetch. For someone landing on the project with their own Node/TypeScript project, there is no clean `npm install` entry point.

The SDK is the missing layer between the familiar API and developer projects. It should feel like the obvious way to call familiar from code — not a heavy framework, just a thin typed wrapper over the HTTP API.

## Ideation

The mental model from the product owner:

> "I'd have my project and inside my project I'd use the API calls like I'd hook it up with code. I'd use an npm package."

The SDK is the integration surface. The CLI (`@familiar/cli`) is the operator surface. They serve different audiences:

- **SDK** — what developers `npm install` in their projects to send input, sync tools, handle webhooks
- **CLI** — what the familiar operator uses to manage accounts, set keys, run portals

curl stays as a valid path for the API — the SDK does not replace it, it complements it.

**Settled scope for MVP:**

The three things a connected system actually does (from `provider-api-direction.md`):

1. Send conversation input — `familiar.input()`
2. Sync tools — `familiar.tools.sync()`
3. Handle executor callbacks — webhook shape the SDK can help with

Plus account bootstrap so a new developer can go from zero to running in one file:

4. Create account — `Familiar.createAccount()`

**What the SDK is not:**

- Not a framework
- Not an abstraction over multiple AI providers
- Not a replacement for curl — raw API calls stay valid

**DX target:**

```typescript
import { Familiar } from "@familiar/sdk";

const familiar = new Familiar({ token: "fam_..." });

const result = await familiar.input({
  text: "Start a countdown",
  channel: { type: "web", id: "session_123" },
});
```

## RFC

### 2000ft View

`@familiar/sdk` is a thin TypeScript client package that lives at `packages/sdk/` inside this repo. It wraps the familiar HTTP API with typed methods, exports full TypeScript types, and has zero runtime dependencies. It is built with `tsc` and published to npm independently of the worker app.

The root `package.json` (the worker app / `@familiar/cli`) stays unchanged. The SDK is a standalone subdirectory with its own `package.json`, `tsconfig.json`, and `src/`.

### Package Structure

```
packages/sdk/
  src/
    index.ts       — exports Familiar class and all types
    client.ts      — core HTTP helpers
    types.ts       — all public types
  dist/            — built output (gitignored)
  package.json     — name: @familiar/sdk
  tsconfig.json
  README.md
```

### API Surface

```typescript
// Bootstrap (static — no token needed)
const { token, account } = await Familiar.createAccount({ host? })

// Instance
const familiar = new Familiar({ token, host? })

// Send conversation input
familiar.input({ text, channel, userId?, threadId?, integrationId?, tools? })

// Sync tools
familiar.tools.sync({ tools })

// Inspect integration
familiar.integration.get()
familiar.integration.update({ aiApiKey?, baseUrl? })
```

### Types

```typescript
type Channel = { type: string; id: string; name?: string }
type Tool = { toolName: string; description: string; inputSchema: object; inputMode?: "processed" | "raw"; status?: "active" | "inactive" }
type InputResult = { threadId: string; messages: Message[]; execution: { state: string } }
type FamiliarError = { code: string; message: string }
```

Errors throw a `FamiliarError` instance (extends `Error`) with a `code` field.

### Behaviour Spec

**GIVEN** a valid token  
**WHEN** `familiar.input({ text, channel })` is called  
**THEN** returns a typed `InputResult`

**GIVEN** an invalid token  
**WHEN** any method is called  
**THEN** throws `FamiliarError` with `code: "unauthenticated"`

**GIVEN** no AI key set  
**WHEN** `familiar.input()` is called  
**THEN** throws `FamiliarError` with `code: "configuration_required"`

### Implementation Breakdown

- `[NEW]` `packages/sdk/src/types.ts` — all public types
- `[NEW]` `packages/sdk/src/client.ts` — `request()` helper with error handling
- `[NEW]` `packages/sdk/src/index.ts` — `Familiar` class
- `[NEW]` `packages/sdk/package.json` — `@familiar/sdk`, exports `./dist/index.js`, `./dist/index.d.ts`
- `[NEW]` `packages/sdk/tsconfig.json`
- `[NEW]` `packages/sdk/README.md`

### Invariants

- Zero runtime dependencies
- Works in Node 18+, Deno, Bun, and modern browsers (uses native fetch)
- All public methods return typed results or throw `FamiliarError`
- Token never logged

## Implementation

Created `packages/sdk/` with:

- `src/types.ts` — all public types (`Channel`, `Tool`, `InputResult`, `Integration`, `FamiliarError`, etc.)
- `src/client.ts` — `request()` helper, `FamiliarError` class
- `src/index.ts` — `Familiar` class with `input()`, `tools.sync()`, `integration.get()`, `integration.update()`, static `createAccount()`
- `package.json` — `@familiar/sdk@0.1.0`, zero runtime deps, ESM + types exports
- `tsconfig.json` — strict TypeScript, NodeNext modules
- `README.md` — install, quick start, all methods, error handling

Build: `tsc` → clean, no errors. Smoke test: all exports verified.
